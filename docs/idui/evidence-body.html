00 · The claim under test

One Method, Two Products

Not "we rebuilt a page with less CSS". The earlier transfer test was self-confirming - IDUI specimens rebuilt on IDUI. This one is not.

A methodology derived from one dark-glass hospitality application can express a visually unrelated existing product without importing that application's visual constitution.

Flipgazine's page is the adversary: seven style blocks of its own, a shared header, a WebGL atmosphere, a glyph field, a theme engine that rewrites the palette eight times a day, Poppins at 300 / 500 / 600, tracked uppercase labels and pill controls. None of it was designed with IDUI in mind, and almost none of it looks like Sindhorn.

If the test forces Sindhorn assumptions out of the core, that is evidence for the methodology, not against it - and every such assumption is recorded in the falsification log below. If it cannot express the page without page-level CSS, the claim fails.

01 · Protocol

Frozen Before The After

Eight steps, written down and committed before a single after-metric was taken, so the result could not shape the test.

  1. Snapshot the original page and everything it loads, as stored in Flipgazine's site_files. Nothing in Flipgazine's repository or database is modified; its anon key is redacted from the carried source.
  2. Measure every before-metric automatically, in a real browser, on a pinned clock and a pinned period. Every Supabase read the page makes is answered from disk; no request reaches the live project.
  3. State which engines stay untouched - fg-atmos.js (WebGL atmosphere), fg-glyph.js (glyph field), fg-theme.js (period palette, editorial and legacy modes), fg-motion.js, fg-clock.js. They are environmental engines, not interface. IDUI governs the interface's relationship with them and does not absorb them, the way it does not own Betta's fin shader.
  4. Define parity in layers: functional, identity, visual.
  5. Record every core assumption the migration disproves.
  6. Rebuild through constitution and primitives only. The conversion is a deterministic class mapping; the after page may carry no CSS and no style attribute. Where the library has no primitive, one question is asked before anything is added to the core: is this a reusable semantic degree of freedom required by multiple legitimate constitutions, or one application's historical exception?
  7. Measure exactly the same metrics afterward, same harness, same clock.
  8. Publish wins and losses, including raw total CSS bytes even where the shared foundation is larger than the page it replaced.

Parity, in layers

FunctionalSame content, same information hierarchy, same interactive capabilities - copy buttons, section rail with scroll tracking and smooth scroll, fullscreen, theme and editorial toggles - same state transitions.
IdentitySame face and weights, same tracked labels, same palette through the day, same shape language, same atmosphere. A reader who knows Flipgazine recognizes it.
VisualAs close as the constitution and primitives can reach. Every deviation is declared, none is patched in page code.

Asked and refused

Capabilities Flipgazine has that were not added to the core, because they fail the question is this a reusable semantic degree of freedom required by multiple legitimate constitutions, or one application's historical exception?

The catalog book-thumbnail tilt and hover liftOne application's motif; stays in its engine.
The header's saturate(1.4) against saturate(1.3) on the pageA drift, not a decision; the constitution names one recipe. Recorded as a visual deviation.
The editorial / legacy palette switch and the eight-period themeEngine behavior; the core sees only the tokens the engine writes.
Two status slots the core demands and Flipgazine never hadRecorded the other way round: --app-success and --app-danger are a vocabulary this product never needed. Flipgazine fills them with its accent and muted ink. The one place the core's shape shows through the constitution, left visible on purpose.

What did not change

The seven-sheet contract, the load order (fonts → glass → components → compositions → shell → tokens last), the nine invariants, the glass membership rule, the blur-drop rule for nested glass and the primitive set - .app-card, .app-control, .app-overlay, .app-surface, .app-prose, .app-hero, .app-section, .app-masthead, .app-navbar, .app-code-block, .app-table, .app-step, .app-switch, .app-chip - carried the page without a page-level rule.

The set has moved since this test ran. Invariant 1 named a file — every fill, border and blur comes from app-glass.css — and Test 02 falsified the universal reading of it; r53 restated it as material has one authority, with the glass family becoming Sindhorn's own constitutional law. Nothing measured on this page changes: the rebuild loaded the sheets it loaded, and this is recorded as it happened.

Three core rules were added, all behavioral, all general: a control inside a code block drops its blur (nested glass); a contents list (data-mode="contents") reads as navigation rather than as running-text links; data-columns="2" lets a list run in two columns from 640px.

07 · Parity

How Close It Came

Three layers, judged against the frozen definitions. Two met; the third close, with every deviation named and none patched in page code.

Functional

Met

Same 21 sections, same table of contents, same notes, quotes, commands and tables; copy buttons copy and say "Copied"; the rail tracks scroll, smooth-scrolls, writes the hash and restores it; fullscreen, theme and editorial switches call the same engine entry points; the atmosphere and glyph field self-drive as before.

Identity

Met

Poppins 300 / 500 / 600 from the constitution; tracked uppercase labels (.12em); the theme engine's ground, ink, accent and glass, changing through the day under the core without the core knowing; 14 / 12 / 8 radii and pill controls; the same atmosphere.

Visual

Close, with deviations

Each deviation is either a constitution value the core reads once where the page had several, or a core rule the page does not get to override. Before → after:

  • hero top padding 48–110px → the composition's 28px
  • hero button: accent-tinted uppercase → glass sentence-case primary
  • copy chip: 8px radius uppercase "COPY" → pill "Copy" (the constitution has one control radius)
  • header icon buttons 34×30 → 30×30; icon mark 15px → 18px
  • note label 10.5px → 11px (wraps in one place)
  • h3 weight 600 → 500
  • active rail chip: border only → border + tint
  • prose gap 12 → 14px; contents list 13.5 → 14.5px; section spacing differs by a few px
  • header saturate(1.4) → 1.3 (one recipe)
  • the rail is centered to the page at desktop where the original hugged the left
  • no arrival fade, no selection color, no scrollbar styling - none is a semantic degree of freedom the core offers yet
  • the header row is not re-centered to 1240 at desktop

08 · Verdict

Held, After Nine Corrections

The claim under test - one dark-glass hospitality application's method can express an unrelated product without importing that application's constitution - held, but only after nine core assumptions were moved out of the core. The core that came out is smaller in what it decides and identical in what it renders for Sindhorn: 0 differing pixels on /ci, / and /voice, ratchet unchanged.

Wins

{{before.discretionary}} → {{after.discretionary}} appearance decisions in the page; {{before.blurRecipes}} → {{after.blurRecipes}} blur recipes; {{before.nestedGlass}} → {{after.nestedGlass}} nested glass; every named change now one edit; 0 CSS, 0 !important, 0 inline styles in the page; the page's own script less than a third of the size.

Losses

{{loadRatio}}× the CSS bytes for a one-page product; {{after.backdropCount}} glass elements against {{before.backdropCount}}; the visual deviations above; two status tokens the core demands that Flipgazine never needed.

Not tested

A light theme; motion beyond what the carried engines drive; a second external product. Nothing was deployed to Flipgazine; its repository and database are unchanged.
