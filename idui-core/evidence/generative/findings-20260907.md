# Findings, 7 September 2026

Classified against the frozen taxonomy: **A** misowned core assumption,
**B** constitution, **C** missing reusable capability, **D** product-specific,
split **D-B** behaviour (healthy) and **D-P** presentation (the alarm).

Test: IDUI Test 04 (see `PROTOCOL.md` amendment A3).

## B-01 — A constitution range permitted figure/ground collapse

`palette.baseLightness.min` was 0.15 and `palette.backgroundLightness.max` 0.08,
so the two could be sampled 0.07 apart against a 0.08 separation threshold. 180
of 100,000 seeds collapsed (0.18%).

The generator held no literal bound and made no decision — the constitution's
own declared range permitted the failure. That is the finding: **a generator
with zero appearance decisions is not sufficient for constructional validity if
the constitution's ranges are not themselves closed under the contracts.**

Corrected by raising `baseLightness.min` to 0.18 so the separation holds by
construction. Numbers in `tier-a-20260907-android.json`, both states.

## B-02 — The constitution does not declare its arithmetic precision

The existing macOS generator (`BettaRandomStyleStore.swift`) samples in `Float`;
the web engine samples in a JS `Number`; both Test 04 implementations sample in
64-bit doubles. The raw u64 stream is identical in every case — the derived
values are not.

A value sitting on a contract boundary can therefore pass on one platform and
fail on another, while every implementation is "correct". The frozen protocol
names cross-platform determinism as a contract in its own right, so **the
precision the ranges are sampled in is constitution-level, not an implementation
detail.** It is currently undeclared.

This did not bite: both implementations chose doubles and matched to the bit
(`determinism-20260907.json`). It was avoided by choice, not by rule, which is
exactly the kind of thing that later gets "fixed" by someone matching the
existing `Float` store.

**Proposed, not applied:** the constitution declares its sampling precision.
That is a change to the constitution and needs the owner's approval.

## C-01 — No shared conformance suite between implementations

Determinism was checked by writing a dump mode into each implementation by hand
and diffing the files. Nothing prevents the two from drifting apart tomorrow; a
third implementation would need the same work again, written the same way, or
the comparison stops being meaningful.

The reusable capability that is missing is a **conformance fixture**: a file of
seeds and expected bit patterns that any implementation of this constitution
must reproduce. The evidence series already learned this shape once — the README
warns that per-test harnesses must share metric definitions or "a comparison
between tests measures the measurer."

## D-P-01 — The rendered form sits off-centre (unresolved)

The single Android capture (`observations-20260907-render-smoke.md`) shows the
form right of centre with a large empty area to its left. The angular sweep is
centred on `theta = 0`, which puts most of the fan on the +x side of the mesh
origin, while the framing looks at the origin.

**Unresolved.** The owner has not seen and accepted a corrected version, and per
the evidence law a D-P stands only against an editorially accepted result. Zero
D-P with rejected fidelity is unresolved, not a win — and this is not even zero.

## Procedural finding — measurement ran ahead of frozen predictions

The evidence law requires predictions to be frozen before measuring, on their
own commit. `PROTOCOL.md`'s Q01–Q05 were written for the JS `betta-random-2.js`
sequence, which amendment A3 records as never run. **This incarnation has no
frozen predictions of its own, and the results in this batch were measured
without any.**

They are therefore recorded as baseline observations, not as tests of a
prediction. Nothing in this batch may be cited as a prediction confirmed.
Predictions for the specimen-surface and Tier B phase are to be frozen on their
own commit before that phase is measured.

## Standing caveat on the contracts themselves

No contract in this batch has been exercised by a negative control. A contract
that has never failed on purpose has not been shown to work — the series has
already paid for this once, when a token scan proved text was written rather
than readable and four declarations sat dead for six releases. Negative controls
are to be run before any Tier B result is trusted.
