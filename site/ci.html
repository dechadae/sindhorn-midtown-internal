01 · Material

One Frosted Material

A card is anything that draws an edge, so it needs the atmosphere behind it. A layout container draws no edge and takes no material. Three primitives, declared in markup, defined once in app-glass.css.

.app-card30% fill · 18px blur

Frosted, not painted

The atmosphere stays visible through the surface while its detail is softened by the one blur used everywhere in the app.
.app-controlsame material

Controls share the material. Size and emphasis change by role; the interaction grammar does not.

.app-overlay72% fill · floats above content
A dialog, sheet or menu floats above page content rather than the atmosphere, so it carries more pigment. One material, two weights.
Nestingenforced, not documented

Outer card

A card inside a card keeps the tint and loses the blur. It cannot sample the page — only its parent — so glass inside glass would render as a flat tint whatever the CSS asked for.

Every specimen above is already frosting the thing this page is rendering over right now — it needs no showcase of its own, only an explanation.

04 · Shape & Motion

Rounded, Never Circular

Corners are soft; UI chrome is never a circle or a capsule. Motion explains state and settles with one easing family — press the controls below to feel it.

Surface--radius-surface 14px — cards, disclosures, dialogs
Inset--radius-inset 10px — fields, chips, menus
Press--motion-fast 160ms — immediate feedback
State--motion-ms 280ms — component settles
Reveal--motion-reveal 920ms — data draws itself in (see 12 Metrics)
View--motion-view 300ms, --motion-view-travel 32px — one page gives way to the next (see 18 Shell)
Easing--motion-ease cubic-bezier(.22, 1, .36, 1) for a control settling; --motion-ease-inout ease-in-out for a page or a navbar set moving into place
ReducedReduced motion removes transitions without hiding state
Press160ms · motion-ease · transform

Every control scales down by the same amount, on the same curve, on press. This is the live transform transition declared in app-components.css, not a recording of it.

State280ms · motion-ease · height / rotation

A component settling into a new state — a disclosure opening, a selector's chevron turning — uses --motion-ms with --motion-ease. See 06 Disclosure and 08 Selector: the same two tokens, never a second value invented in a route.

Animation1.4s loop · motion-ease

The one continuous animation in the system. See 21 Skeleton for the full placeholder this pulse belongs to.

Reduced motionduration → .001ms, state unchanged

A prefers-reduced-motion: reduce query resets these same selectors' transition and animation durations near zero. It is not a second, motion-safe copy of the component — the reduction is a media query on the one rule above.

07 · Forms

Forms Stay Quiet and Explicit

Labels stay visible. An input reads as a recessed well rather than a raised surface, so it keeps its own inset tint instead of the card's fill — but it still draws an edge, so it still frosts.

.app-fieldlabel · input · note

Explain what the user can correct.

.app-field textarea · datetime-locala paragraph · a moment

A paragraph takes the same well as a line, tall enough to read what was written; the employee may grow it. A moment is typed into the well too — the browser's own picker opens from it, but the field keeps its edge and height. Times are the hotel's (Asia/Bangkok).

.app-field > .app-codesix wells · type, paste or autofill

A code is one field with six wells, so what was typed is visible at a glance. Typing advances, backspace retreats, a pasted code fills the group. The first well accepts a one-time-code autofill for the whole group.

.app-field.app-searchglass · clear appears with text

The same well as any field, with the glyph inside its left edge and a clear control inside its right that exists only while there is text to clear. Search is a field, not a card, so it draws no second frame.

.app-code-displaysix wells · read only · shown once

The read-only twin of the code field: the code an admin issues is shown in the same six wells the employee will type it into, at title size so it can be read across a desk.

08 · Selector

One Selector, One Menu

The trigger is a control; the menu floats above content, so it is an overlay. There is one selector in the app and this is it.

.app-selecttap to open
Outlet
.app-chipmetadata / filter

A chip is a filter or a piece of metadata, never decoration applied to a short label.

.app-field > .app-chip-groupone of a few · several

When the answer is one of a few, or several from a short list, chips answer a field. The chip carries aria-pressed; a one-of group releases the others, a many-of group does not. Longer lists take the selector or a check list instead.

09 · Actions

One Tactile Language

Emphasis changes by role, not by inventing a new interaction. Utility actions are deliberately frameless: no edge, so no material.

Controlsmaterial
View artwork folder

Disabled dims the content, not the element. Fading a whole button with opacity fades its blur too, so it stops looking like the same material as everything around it.

Utility actions.app-utility-row · no frame · no material

These draw no edge, so by the rule they are not cards and take no glass. That is a consequence of the definition, not an exception to it. A row of them is .app-utility-row: right-aligned always, so Sign out, Share, Refresh and Back to top sit at the same edge on every page.

Back / close controls.app-control · frame is the point

These do draw a frame, so unlike a utility action they take the material — the opposite reading of the same rule. Every icon-only control is one square, --size-icon-control (36px, an 18px mark): a close mark is the same size in a dialog head, in the masthead account chip and here.

.app-railsticky under the masthead · chips jump within a detail

The rail has no edge and no material; each chip frosts on its own, so a sticky row never becomes glass over glass. It stays put at one band below the masthead while the section it belongs to scrolls.

.app-rail data-columns="3"a longer rail wraps to rows of three

Fixed columns keep every chip readable at phone width; a section reached through a two-row rail lands below both rows.

10 · Dialog

One Dialog Standard

Editing and bounded secondary tasks use a native dialog. Do not build a second scrim, scroll lock or open animation.

.app-dialognative <dialog> · .app-overlay

The scrim is not a card: it dims the page behind rather than sitting on the atmosphere, so it owns its own values.

confirmDialog()app-dialog.js · asked from code

A page that needs a yes-or-no moment calls confirmDialog({ kicker, title, copy, confirm, cancel, tone }) and awaits a boolean. It builds this same standard, focuses Cancel, and removes itself on close. tone="danger" gives the confirm button the danger ink; Settings › Me uses it for Sign out.

openDialog() · .app-dialog-grida form in the standard · two columns, one on a phone

A page with a form to show - Edit card, Add employee - calls openDialog(markup) with a body of its own and gets the same scrim, Escape and clean-up. Inside, .app-dialog-grid lays fields and selectors two across, data-span="full" takes a row, .app-dialog-section opens a titled group above a hairline, and .app-dialog-status is the one line that says Saving… or explains the error - never a second toast, never an alert.

.app-sheetnative <dialog> · bottom-anchored

Same native <dialog> and overlay material as above; only the geometry changes, because this one belongs to the thumb.

.app-dialog-actions-splitdestructive left · confirm right

A static preview — the modifier only changes justify-content, so it needs no dialog of its own to show.

transitionView()app-view.js · pages arrive, they do not reload

Tap the tabs, the chip, then the tabs again. The old page cuts; the new one arrives --motion-view-travel off its place and settles over --motion-view on plain ease-in-out. A tab to the right pushes in from the right; to the left it pops in from the left. The chip covers: Settings arrives from the foot while the navbar's app set slides out left and the settings set slides in from the right; closing it dismisses — the page beneath returns from the head and the sets slide back. Since r14e the shell itself changes pages with a plain swap — the movements tried on a phone (r13–r14d) each stuttered or switched the glass off — so this specimen is the library’s reference, not what the shell does today; the navbar push is live.

Only the incoming page moves, and only by a transform — nothing recedes, scales or fades. A crossfade is not available to this shell: opacity, filter or clip-path on the moving page, or on anything above it, switches off the backdrop blur beneath and the glass would flash flat mid-move. The host holds its start pose hidden through data-view until the swap lands, so a new page never appears in place and then jumps.

23 · Rules

What Holds the System Together

A card draws an edge.If it draws a border or a fill it is a card and takes the material. If it only arranges children it is a layout container and takes nothing.
Material is declared, never redefined.A page consumes .app-card, .app-control or .app-overlay. No page declares fill, edge or blur of its own.
Glass never nests.A backdrop filter inside a backdrop filter samples its parent, not the page, and renders as a flat tint. The library handles this so a page cannot get it wrong.
Reuse before creating.If a page needs something that is not here, it is added here first and then consumed. A component that exists only inside one route is not a component.
One rhythm between sections.44px between sections, 24px from the hero to the first one, 20px from a title to its content, 12px between cards in a stack, and a hairline between groups inside one card. A page never sets its own gaps.
Secondary text never drops below 11px.Labels, deltas, notes and metadata are 11 or 12px. A rule that shrinks them fails the render gate.
Geometry is never inline.A data-driven length is an SVG attribute or a data attribute the library maps, not a style attribute. The track in 12 Metrics is the pattern.
Status is a tone, not a colour.A card's status, a hero's eyebrow, a badge and a state all speak the same two words — success, quiet — and the library maps them. A page never picks a colour for a state.
One typeface, zero tracking.LINE Seed Sans TH at 100, 400 or 700. Application chrome never adjusts letter spacing.
Rounded, never circular.Corners are soft. Circular and capsule chrome are not part of this system.
Motion explains state.Press is immediate, state settles with one easing family, and reduced motion removes the transition without hiding what changed.
The atmosphere is never covered.No route paints a full-bleed veil over the Betta. Legibility comes from the material, not from dimming the app.
