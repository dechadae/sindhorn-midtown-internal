# Rebuild test — Flipgazine "Moving to Claude Code" on the IDUI core

Run 6 September 2026 under the frozen [`PROTOCOL.md`](PROTOCOL.md). One
page from a product with no IDUI history, rebuilt through the Flipgazine
constitution and the core's primitives, with its WebGL atmosphere, glyph
field, theme engine and motion runtime carried unchanged. What the core got
wrong is in [`FALSIFICATIONS.md`](FALSIFICATIONS.md).

```
node idui-core/evidence/rebuild/convert.mjs    # before → after/claude-code.html (deterministic)
node idui-core/evidence/rebuild/measure.mjs    # both pages, same browser, same clock, same period → comparison.json, shots/
```

Pinned: period `golden-hour`, clock `2026-09-06 19:20 +07:00`, Chromium
via Playwright. Every Supabase read the before page makes (`site_files`
module loads, the period fetch) is answered from `flipgazine-source/` on
disk; no request reaches the live project. Google Fonts is fetched live by
both pages, so both render Poppins.

### Source: the shared foundation (the loss)

| | bytes | rules |
|---|---|---|
| core (`app-glass` + `app-components` + `app-compositions` + `app-shell`) | 82,011 | 434 |
| Flipgazine constitution (`app-tokens.css` + `fonts.css`) | 5,866 | 6 |

The after page loads **2.9× the CSS bytes** the before page authored
(87,877 against 30,693). Published as a loss, as the protocol requires. The
comparison is not like for like — the before figure is one page's CSS and
the after figure is a foundation that carries every page of a product — but
for a product with one page, IDUI costs more bytes, and this test does not
pretend otherwise. Of the 434 core rules, this page exercises perhaps a
third; the rest is the price of not writing them again on the next page.

out only by rewriting the rule, which it may not.

## Parity

**Functional** — met. Same 21 sections, same table of contents, same
notes, quotes, commands and tables; copy buttons copy and say "Copied";
rail tracks scroll, smooth-scrolls, writes the hash and restores it;
fullscreen, theme and editorial switches call the same engine entry
points; the atmosphere and glyph field self-drive as before.

**Identity** — met. Poppins 300 / 500 / 600 from the constitution; tracked
uppercase labels (`.12em`); the theme engine's ground, ink, accent and
glass, changing through the day under the core without the core knowing;
14 / 12 / 8 radii and pill controls; the same atmosphere.

**Visual** — close, with these declared deviations (before → after). None
is hidden and none was patched in page code; each is either a constitution
value the core reads once where the page had several, or a core rule the
page does not get to override:

- hero top padding 48–110px → the composition's 28px
- hero button: accent-tinted uppercase → glass sentence-case primary
- copy chip: 8px radius uppercase "COPY" → pill "Copy" (the constitution has one control radius)
- header icon buttons 34×30 → 30×30; icon mark 15px → 18px
- note label 10.5px → 11px (wraps in one place)
- `h3` weight 600 → 500
- active rail chip: border only → border + tint
- prose gap 12 → 14px; TOC list 13.5 → 14.5px; section spacing differs by a few px
- header `saturate(1.4)` → `1.3` (one recipe)
- the rail is centered to the page at desktop where the original hugged the left
- no arrival fade, no selection color, no scrollbar styling (the original page had all three; none is a semantic degree of freedom the core offers yet)
- the header row is not re-centered to 1240 at desktop

## Verdict

The claim under test — one dark-glass hospitality application's method can
express an unrelated product without importing that application's
constitution — held, but only after nine core assumptions were moved out
of the core (see the falsification log). The core that came out is smaller
in what it decides and identical in what it renders for Sindhorn (0
differing pixels on `/ci`, `/index`, `/voice`; ratchet unchanged).

Wins: 356 → 0 appearance decisions in the page; 5 → 1 blur recipes;
3 → 0 nested glass; every named change now one edit; 0 CSS, 0 `!important`,
0 inline styles in the page; the page's own script a third of the size.

Losses: 2.9× the CSS bytes for a one-page product; 90 glass elements
against 38; the visual deviations above; two status tokens the core demands
that Flipgazine never needed.
